If the existing validator is invoked verbatim, its record says `labels_used_for_selection=true` because it was designed for the old search; this audit's new cells are locked comparisons and must not use the validation metric for selection. Source-community coverage may be reconstructed from the fixed graph/plan with the same method for every depth, visibly labeled as a candidate or simulated quantity.

## E6 per-anchor count-matched Kwide

**0/9 exact Kwide cells are reusable.** The only historical `kwide_countmatched` records for these cases are `BASE/multihop_mechanism_20260924/outputs/step5/Baron/kwide_countmatched/seed_<seed>/record_seed_<seed>.json`, all three complete, but their reference is **Baron H8_B1 q=2, amplitude=1**. The selected E4/E6 Baron pair is H8_B1 **q=1**, amplitude=1; even its historical H1 mechanism arm is based on the q=2 comparison. Quake and student_grade have no historical count-matched records. None of these substitutes is an exact case pair.

`BASE/multihop_mechanism_20260924/step5_interventions.py:run_task(task_path, output_dir, device)` and its `--task-json`, `--out`, `--device` CLI implement a traceable control. The task requires dataset, seed, arm=`kwide_countmatched`, `locked_record`, `tuning_manifest`, `input_kind`, and `feature_limit`. Its `intervention_plan.transform_plan` builds cosine-nearest direct candidates with **the same count for each anchor** as the selected path plan and keeps four draws; it recomputes candidate probabilities, so actual displacement and source mass can change. The worker saves model, embedding, predictions, fitted preprocessor, source trace, per-anchor displacement, hop audit and artifact hashes. `trace` is realized finite-draw training exposure for that new arm. Core `Kwide2`/`Kwide3` variants match only H2/H3 reference plans and cannot represent the requested H8 or H4 count match.

The Step5 wrapper currently rejects any locked reference whose variant does not start `H8_`, so Quake H8_B2 and Baron H8_B1 can use its API with the correct q=1 records, but student_grade H4_B1 requires a bounded wrapper change outside the historical core. The transform itself accepts an H4 fixed candidate plan; the guard is the immediate blocker. The E6 comparison must pair each new arm against its **same seed, same selected path config**, and report ARI, actual source coverage/coassignment, candidate count, four-draw count, and displacement. It is a strategy comparison, not a claim that path identity alone was isolated.

Check that the clean extracted embedding matches the saved `embedding_seed_*.npz` before interpreting any perturbation result. This is a feasibility audit; that loaded-checkpoint probe was not executed here.
