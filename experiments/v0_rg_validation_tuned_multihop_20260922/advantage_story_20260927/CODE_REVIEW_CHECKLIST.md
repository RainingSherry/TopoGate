## Controller and launch gates

- The controller may schedule only the 21 missing fits and only physical GPU 2 or 4. Set `CUDA_VISIBLE_DEVICES` to the single assigned physical GPU and use `cuda:0` inside that worker; set two CPU threads per worker. Start four workers per GPU only when the measured free memory meets the reserve, then grow toward the approved cap of 16 per GPU as resources permit. Keep the reserve check at every admission, rather than treating 16 as a fixed launch count.
- Require an explicit, externally supplied approval hash bound to the exact queue, experiment code and imported historical core hashes. The controller must verify this hash and must not create or silently update it itself. Record the hash with every task result. Use an atomic per-cell claim so a restart cannot duplicate a live job; adopt still-running claimed workers, and skip a completed cell only after its status, expected config and artifact hashes verify.
- One retry is permitted for a transient failure, then record the failure and continue independent tasks. Incomplete, missing or hash-mismatched outputs are not successful reuse. No task or scheduler branch may read labels during feature preprocessing, graph construction or fit, alter scientific parameters, or select a checkpoint/readout by full-X labels.
