# E5 Baron trace coverage definition audit (2026-09-27)

The reported 38.93% new-community mass and 21.45% same-class/new-community mass come from the **five-seed `flat_anchor` actual training traces**, not a common first-seed graph used for every seed. In `papers/source_coverage_20260925/analyze_cases.py`, lines 179–184 build one fixed Louvain community partition from the first `flat_anchor` seed's reconstructed graph. Lines 196–200 then reconstruct **each record's own graph with that record's seed** and pass its indices to `source_stats`. Lines 89–92 of `source_stats` form each anchor's near-community set from those per-seed graph indices, with the common community IDs. Line 115 counts a traced source as new when its community is absent among that anchor's one-hop source communities and the traced hop is at least 2. Thus “new” means absent from the one-hop source set, not necessarily a community different from the anchor's own community.

The denominator is each anchor's total realized, reweighted neighborhood-mixture mass over its full training trace. The source fractions are computed per anchor and averaged in each seed, then the five seed values are averaged. The fixed community partition makes community IDs comparable across seeds; the seed-specific graph determines whether each community was already reached by that seed's one-hop neighbors. The actual `source_coverage.csv` reports new-community fractions 0.388624, 0.391340, 0.387101, 0.393425, 0.385942 and same-class/new fractions 0.216158, 0.215361, 0.212064, 0.212912, 0.215980, yielding the published means 0.38928652 and 0.21449490. These are overlapping mass subsets before the gate; they are not final-input fractions.

The saved per-seed `outputs/train/Baron/flat_anchor/seed_*/graph.npz` files show why the seed-specific near set matters: compared with seed 1019, the same-anchor one-hop neighbor-set overlap is only 86.80%, 84.86%, 84.84%, and 83.36% for seeds 2027, 3037, 4051, and 5059. `analyze_cases.py` already uses a per-seed graph, so no scientific definition change is needed. For stricter provenance, load each run's saved `graph.npz` indices (or compare them exactly to the reconstruction) before calculating coverage; the current code reconstructs but does not verify that it matches the graph persisted during fitting. Keep the first-seed community partition fixed for the published five-seed statistic, and document its provenance.
