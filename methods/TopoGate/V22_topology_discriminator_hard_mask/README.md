# V22: Topology-Conditioned Discriminator-Guided Hard Mask scMAE

V22 is an isolated exploratory implementation. It keeps the project scMAE
encoder/decoder and adds a coordinate-matched discriminator plus a hard-budget
topology Gate. The primary readout is KMeans on the clean encoder embedding;
no Student-t head is used for the first V22 protocol.

The original `v22_topology_discriminator_hard_gate` is retained as an
adversarial-hard-negative control: it selects coordinates that the discriminator
finds difficult. The intended cooperative variant is
`v22_topology_discriminator_cooperative_keep_gate`. It selects an exact-budget
keep set from eligible donor-changed coordinates, leaves that set visible, and
reconstructs only the complementary coordinates. With the model and
discriminator frozen, its Gate objective minimizes the matched-coordinate
reconstruction plus generator adversarial loss, so Gate and scMAE share a
cooperative objective rather than maximizing discriminator difficulty.

## Data flow

1. The input adapter keeps a sparse support view for graph statistics and uses
   a label-free top-variance cap for the dense scMAE view. `M[i,j] = 1` means
   that the donor value at coordinate `(i,j)` is artificially corrupted and
   the generator must reconstruct it.
2. The topology graph provides four per-coordinate statistics: deviation,
   dispersion, neighbour support, and stability. The topology Gate selects an
   exact per-row budget with straight-through Top-K. Random and non-topology
   controls use the same donor family and effective-change accounting. The
   cooperative variant interprets the selected budget as a keep set; the
   hard-gate variant interprets it as a reconstruction mask.
3. The discriminator sees matched real/fake coordinate pairs with the same
   sample, feature coordinate, latent context, topology context, and candidate
   scalar. It receives neither the source Mask nor a Hint matrix, so it cannot
   classify by a mask shortcut.
4. The generator optimizes scMAE reconstruction plus an adversarial loss on
   selected coordinates. The hard-gate Gate is updated in a separate
   frozen-model phase with the per-pair reward
   `clip(logit_D(real) - logit_D(fake), 0, c) * stability` and a coverage
   penalty. The cooperative keep Gate instead minimizes the matched-coordinate
   reconstruction plus generator adversarial loss on the complementary mask.
   The reconstruction-hard Gate is retained as a negative control; it replaces
   discriminator difficulty with matched-coordinate squared reconstruction
   error. The trainer records D accuracy on Gate fakes versus budget-matched
   random scMAE fakes, matched real/fake support and magnitude summaries,
   value-magnitude-bin accuracy, magnitude-matched D accuracy, and cooperative
   Gate gradient norms split into reconstruction and discriminator components,
   plus selected/effective mask and keep profiles. These diagnostics expose
   corruption shortcuts and D-dominated Gate updates before a formal run.

## Variants

* `scmae_only`
* `scmae_always_visible`
* `scmae_plus_discriminator_random_mask`
* `scmae_plus_discriminator_reconstruction_hard_gate`
* `scmae_plus_discriminator_learned_non_topology_gate`
* `v22_topology_discriminator_hard_gate`
* `v22_topology_discriminator_cooperative_keep_gate`

Run the focused tests with:

```bash
pytest -q methods/TopoGate/V22_topology_discriminator_hard_mask/tests
```

The V22 matrix runner reads a fixed dataset manifest generated by either
`scripts/V22/prepare_dataset_extension.py` or the round-2 preparer and skips
completed canonical `dataset/variant/seed` keys.

The current prototype deliberately leaves the discriminator-before-Gate update
order unchanged. The D confusion and Gate-gradient diagnostics are required
for deciding whether a delayed/target-D schedule is needed; no paper result is
claimed until that diagnostic is reviewed on a multi-seed control matrix.
