# E1–E4、E8–E12 清除记录

本记录对应用户在 2026-08-19 的明确授权。它只改变
`raw_sparse_mask_schedule_probe_v2_shared` 的执行资源策略；v1 文档、v1
结果目录和已发生的 shared-resource engineering-only 运行保留为历史审计记录。

## 已清除

- E1：不再要求目标 GPU 处于 idle。
- E2：外部进程不再阻止启动；不因共享而等待。
- E3：共享 GPU 运行不再自动标成 `shared_resource_engineering_only`。
- E4：取消每卡单 worker 与 occupancy gate；允许显式配置多个 worker slot。
- E8：取消 T0+11h 新启动截止和最终保留时间。
- E9：取消一次 retry 上限；`--attempts 0` 表示持续重试，直到成功或人工停止。
- E10：取消 retry 时必须保持原执行资源配置的限制；后续显式调用可以调整
  retry/resource 参数。模型结果仍按实际配置和 hash 记录，不能静默改写为等价结果。
- E11：取消 dispatch-entry 和 bind 前 occupancy recheck。
- E12：不再要求 v2 启动前重复 v1 P0/P1/tests/compile/freeze gate。

## 仍保留的硬边界

- 物理 GPU 0 和 7 永久禁止；只允许 `[1,2,3,4,5,6]`。
- 不终止、不抢占、不改写外部进程。
- fit/loss/mask/model selection 不接收 `y`、`K`、ARI、NMI 或 ACC；标签只在 fit
  完成后用于外层 readout。
- OOM、timeout、NaN、shape/hash/label-leakage 或协议错误必须记录为
  `incomplete_compute`，不能伪装成成功。取消 retry cap 不取消这一失败语义。
- v2 仍使用冻结的 90-cell 矩阵、三 paired seeds、五个 arm 和既有 SVD32 复用，
  不自动扩展 holdout、模型族或新科学 gate。

当前执行入口：

```bash
python -m scripts.raw_sparse_mask_schedule_v2_shared \
  --dispatch --gpus 1,2,3,4,5,6 --workers-per-gpu 2 --attempts 0
```

v2 的 manifest、resolved config 和 launcher hash 写入
`result/raw_sparse_mask_schedule_probe/V2_SHARED/FREEZE/`；运行结果只从
`V2_SHARED/MAIN/` 聚合，不混入 v1 `MAIN` 或 `SHARED_RESOURCE_MAIN`。
