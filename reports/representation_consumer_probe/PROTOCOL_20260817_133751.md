# Representation-Consumer Probe Protocol

## 0. 研究定位

本项目不是 V-series 版本升级，也不承诺实现 `TopoCut`。它只做 representation-consumer localization：在一个冻结的关系候选池中，分别测量 candidate opportunity、selection utility 和 representation-objective compatibility。

核心假设按顺序检验：

1. `H1`：当前 candidate relation pool 内有可利用的 clustering opportunity；
2. `H2`：现有 selection policy 没有把 opportunity 稳定转成 readout gain；
3. `H3`：在相同输入接口和容量下，cut-aligned objective 比 reconstruction objective 更能利用该 selection。

`H1` 或 `H2` 失败时禁止更换 consumer；`H3` 未通过时禁止实现 strong backbone。

## 1. 研究边界与现有代码事实

V25/E1 的 `N/R/T` 共享 branchpoint、donor、eligible set、effective budget 和 Gumbel schedule，但 `T` 的动作是 batch 内 feature-coordinate assignment corruption。V21/V25 的 `build_svd_knn_graph` 只产生 sample-neighbor candidate graph，现有 `FeatureGate` 并不返回 sample-edge membership。因此：

- 本项目不得把 V25 的 `T` 直接标成 sample-graph `T`；
- S0 必须先产出 `selection_to_relation_adapter.json`，明确输入、输出、预算、随机量和 labels-after-fit-only 审计；
- 若适配合同不能在不看标签的情况下定义 edge membership，则 S1 仅允许 `F/U/R/O_pool/O_full`，报告为 graph-opportunity diagnostic，不得写 `TopoGate(T)` 增益；
- 在适配合同通过前，任何 `T` 名称都写作 `T_adapter_pending`，不得启动 S3。

这条边界避免把“feature intervention 的拓扑统计”偷换成“sample graph selection”。

## 2. 共同数据流

```text
frozen dataset snapshot
        |
        v
label-free common preprocessing -> H0 (primary d0=128)
        |
        +--> candidate relation pool G_candidate=(V,E0)
        |       |
        |       +--> U, R, T_adapter (only after S0 contract)
        |       +--> O_pool / O_full (diagnostic labels only)
        |
        +--> F baseline
        |
        +--> graph-conditioned view V(W,H0) for matched Rec/Cut probes
        |
        v
clean embedding -> known-K KMeans readout -> outer metrics only
```

`H0` 是固定的 TruncatedSVD (`d0=128`, primary)，不随 arm、objective、seed 或结果调整。所有 graph arm 共享同一 `H0`、候选池、权重规则、symmetrization、budget、K protocol 和 paired seed。

进入 S1 前必须提交 [S0_FREEZE.md](S0_FREEZE.md) 的具体数值合同；“稍后冻结”不算协议通过。Oracle 结果不得反向修改其中任何字段。

## 3. 数据与冻结面板

机制压力面板固定为：`cnae9`、`Mouse_retina`、`sms_spam_collection`、`Baron Human`、`Campbell`、`hate_speech`。它们覆盖 V21 历史正、近零和负号，但不是 generalization benchmark。正式运行前必须从当前 E1 manifest 重新解析 source path、source SHA、adapter、K source 和 labels-after-fit-only 状态；不存在或 hash 不匹配的输入标记为 `protocol_mismatch`，不能用近似文件替代。

主 seeds 为 `[42, 123, 7]`，按 dataset × seed 配对；seed 不是独立 population sample。每次运行固定 clean embedding + known-K KMeans primary readout；NMI、ACC、macro-F1 仅为 secondary benchmark metrics。

## 4. 图语义

candidate pool 以 directed row budget 表示；所有 arm 从同一 `E0` 产生，随后使用相同的非负权重函数和确定性 symmetrization：

```text
w_ij = max(cosine(H0_i, H0_j), 0)
W_sym = (W + W.T) / 2
```

row budget 约束在 symmetrization 前审计；symmetrized edge count、degree、isolates 和 components 单独记录。禁止使用可能为负的 raw cosine 直接构造 normalized Laplacian。

## 5. 标签边界

普通 arm `F/U/R/T_adapter` 的 preprocessing、candidate construction、selection、view transform、loss、optimizer 和 model update 禁止接受 `y/labels/ground_truth`。标签只可在外层用于：

- benchmark-known `K`；
- `O_pool/O_full` diagnostic graph construction；
- edge purity、candidate recall、ground-truth NCut 和最终 ARI/NMI/ACC/F1 评估。

Oracle artifact 必须单独保存 `oracle_manifest.json`，写明 `labels_used=true`、`purpose=diagnostic_only`、`method_claim=false`。训练器只接收 `X/H0/W/K`，不接收标签。

## 6. 共同 artifact contract

每个正式 run 至少保存：

```text
resolved_config.json
dataset_manifest.json
candidate_graph.npz
selected_graph.npz
graph_metrics.json
embedding.npy
predictions.npy
training_metrics.csv
summary.json
audit.json
```

Oracle 追加 `oracle_manifest.json`；SimpleCut/Rec/Cut 追加 `representation_diagnostics.json`（effective rank、dimension variance、distance profile、graph energy）。状态只能是 `completed_valid`、`invalid_design` 或 `incomplete_compute`，不能用缺文件的目录参与汇总。

## 7. 阶段顺序

```text
S0 Freeze / adapter audit
  -> S1 graph-only oracle + spectral
  -> S2 SimpleCut + failure map
  -> S3 matched Rec/Cut objective isolation
  -> S4 strong backbone validation (conditional)
  -> S5 frozen holdout (conditional)
  -> S6 paper-scale expansion (conditional)
```

每一步都必须先写阶段 decision artifact。阶段失败立即停止，不用后续模型“解释”前一阶段失败。
