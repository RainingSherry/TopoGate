# Representation-Consumer Probe

这是一个独立的机制研究项目，项目 ID 为 `representation_consumer_probe`，不属于 V 系列，也不预设会产生新的 TopoGate architecture。

## 研究问题

在固定的公共 feature stem、candidate relation pool、edge budget、readout 和 seed 下，聚类机会的损失究竟发生在：

```text
candidate construction -> selection -> representation consumer -> topology value
```

项目只在证据依次支持 `opportunity`、`selection gap` 和 `objective interaction` 时才允许实现 cut-informed consumer。任何阶段通过后才解锁下一阶段；没有性能结果可以从本目录的协议文件推出。

## 当前状态

`protocol_draft_not_authorized`。本次只建立协议、预注册、审查包和结果目录，不启动训练、下载数据、GPU 队列或新模型实现。

V25/E1 的结果只是动机和适配输入：它是 known-K、labels-after-fit-only 的 feature-assignment case study，不能被重述为已有 sample-edge selector 证据。这个边界是本项目 S0 的第一条验收条件。

## 结果目录

正式结果只能写入 `result/representation_consumer_probe/`，并按 `S0_freeze` 至 `S5_holdout` 分层。每个 job 必须保存 resolved config、输入/协议来源、图和 budget 审计、embedding、predictions、metrics、history、audit 与状态；当前目录为空，不得把 smoke 预先当成结果。

## 审查治理

协议修改采用 `auto-review-loop`：每一轮保存完整 Claude review 请求/响应、reviewer memory、state 和 trace；外部路由失败时保留失败边界，不能把本地意见写成外部 acquittal。Codex 负责最终裁决，reviewer 建议只有在不改变研究问题和证据边界时才纳入。
